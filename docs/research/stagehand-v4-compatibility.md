# Stagehand v4 observation compatibility

Research checked on 2026-09-30 for [issue #8](https://github.com/Mochib-Tech-Solutions/xpathed/issues/8). Evidence below comes from official documentation, package metadata and pinned source inspection. The initial research inspected sources without executing the SDK. The subsequent implementation pins 4.1.0 in an isolated evaluation adapter; source evidence below does not itself establish runtime compatibility or comparison scores. Commands and accepted policies live in [independent evaluation](../evaluation.md#compare-the-custom-resolver-and-stagehand).

Subsequent implementation and runtime measurements are recorded in the [comparison pilot report](stagehand-comparison-report.md). The source-inspection limitations below describe the research stage, not the later validation.

## Release and local browser attachment

The npm registry reported `@browserbasehq/stagehand@4.1.0` as latest, requiring Node `>=22.18.0`. Its Git tag resolves to commit `cd7b230778cf92269e4cb90e80d97f5113781c51`, tagged on 2026-09-09. Search-indexed GitHub release results still showed 3.7.3, so they were insufficient evidence for selecting the current release. Pin the exact package version and lockfile integrity if this candidate passes the gate. [npm metadata](https://registry.npmjs.org/@browserbasehq%2fstagehand/latest), [tag record](https://api.github.com/repos/browserbase/stagehand/git/tags/308bd2b0def8807ab7afa75bc62a1612db3c143c)

v4 supports `localBrowser.connect({ cdpUrl })` without Browserbase hosting. It loads a bundled extension from the SDK host's filesystem, or attaches using an existing `extensionId`. Default attachment therefore requires the SDK and browser to share the extension path. Extension debugging requires `--enable-unsafe-extension-debugging`; connection cleanup leaves an externally launched browser running. Validate these requirements inside an isolated evaluation stack, preserving the production browser's ownership, sandbox and origin boundaries. [Browser documentation](https://docs.stagehand.dev/v4/configuration/browser#connecting-over-cdp), [pinned browser factories](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/sdk-ts/src/browser/factories.ts), [pinned extension loading](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/sdk-ts/src/cdpClient.ts)

## OpenRouter and request accounting

The pinned built-in model configuration accepts five providers and enumerated model names, with no custom base URL. Use the documented `model: { generate }` client callback for OpenRouter instead of copying v3 `llmClient` or `baseURL` examples. Stagehand supplies its prompt and requested JSON schema; the callback returns structured content and optional usage. Source inspection establishes this extension point, not compatibility with a particular OpenRouter route. [Pinned custom-model documentation](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/docs/v4/configuration/models.mdx#custom-models), [callback schema](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/sdk-ts/src/clientSchemas.ts#L196), [model configuration](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/protocol/schemas.ts#L843)

Proposed adapter policy: issue one bounded request through the same standard OpenRouter route, preserve Stagehand's prompt/schema, and record the provider generation ID, reported cost, usage and errors in the shared spending ledger. Retain estimated and reported charges separately, including failed attempts. Stagehand's usage shape lacks provider-reported USD cost, and observation defaults missing token usage to zero; that metadata cannot establish zero spend or replace the ledger. Route settings, output limits and failure-charge recovery remain to be verified. [Protocol usage/results](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/protocol/schemas.ts#L507), [observation usage conversion](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/extension/inference.ts#L174)

## Observation, cardinality and selectors

`observe(instruction, { page })` returns `{ data: Action[], metadata }`; each action includes a selector, description, method and arguments. Its prompt asks for matching elements or an empty array. The implementation captures a snapshot, performs inference and maps selected element IDs to selectors without calling `act`. The result does not enforce one shared action type, distinct targets, completeness or xpathed readiness states. [Pinned observation service](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/extension/services/observeService.ts), [observation prompt](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/extension/prompt.ts#L143), [explicit page selection](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/sdk-ts/src/stagehand.ts)

Issue #8 currently requires first-ranked selection for singleton comparisons: a wrong first suggestion stays wrong even if a later suggestion matches the oracle. Its assignment clarification also prohibits counting one suggestion as complete success for a plural request. [ADR-0014](../adr/0014-resolve-one-action-across-current-page-targets.md) defines the current product as one action across a target set. The user accepted whole-set plural grading on 2026-09-30: normalize all returned suggestions for explicit plural instructions and grade missing, extra, duplicate and wrong nodes separately. Preserve the first-ranked singleton rule and report the two categories separately. Neither path may use expected labels to select better suggestions. [Current issue wording](https://github.com/Mochib-Tech-Solutions/xpathed/issues/8)

Stagehand maps model-selected frame/backend-node IDs to generated `xpath=...` selectors; actions carry no separate frame identity. Its path helpers concatenate iframe host and child-document paths and reserve `//` for shadow hops. These paths require Stagehand-aware interpretation and must not be presented directly as ordinary document-scoped XPath. The observation loop skips unmappable IDs and does not independently verify returned selectors against their original nodes. A comparison adapter needs explicit frame conversion and independent identity checks; unsupported conversion must remain distinguishable from no target or operational failure. Do not expand shadow-root support to accommodate these selectors. [Selector mapping](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/extension/services/observeService.ts), [frame/path helpers](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/extension/understudy/a11y/snapshot/xpathUtils.ts)

## Calls, retries and caching

Pinned observation makes one structured-generation invocation. The client-callback path adds no retry loop; the adapter should likewise avoid automatic retries or model fallback. The built-in AI SDK path does not explicitly set `maxRetries`, so one observation must not be assumed to mean one HTTP request on that path. Count actual provider requests rather than inferring them from primitive calls. [Inference](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/extension/inference.ts#L174), [callback execution](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/extension/llm/clientLlmClient.ts), [built-in generation](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/extension/llm/aiSdkClient.ts#L195)

Managed cache requires a Browserbase API key and session; local observation has no such cache context. The pinned source defaults managed caching to false, whereas current observation documentation describes an enabled default. Use pinned behavior for the comparison and still verify runtime call counts; provider prompt caching is separate from saved observation reuse. [Pinned cache prerequisites/default](https://github.com/browserbase/stagehand/blob/cd7b230778cf92269e4cb90e80d97f5113781c51/packages/extension/services/cacheService.ts#L50), [current observation documentation](https://docs.stagehand.dev/v4/basics/observe#server-side-caching)

## Compatibility gate

1. Pin 4.1.0 in an isolated evaluation adapter and prove local extension attachment and explicit page targeting without provider calls.
2. Use deterministic callback responses to verify schema plumbing, empty results, wrong-first selection, errors, frame conversion and independent XPath identity grading. Keep action execution and self-healing out of the adapter.
3. Verify the accepted whole-set plural policy, preserving the first-ranked singleton comparison and separate denominators.
4. Only then perform a minimal live OpenRouter check within the authorized shared budget, capturing actual requests and reported charges. Match supported route/settings or label the result a whole-configuration comparison.
5. Retain incompatibility evidence and select another explicitly pinned release or report a blocker if the candidate fails. Do not turn source-level compatibility into an invented accuracy score.

Runtime unknowns are local Chromium/extension compatibility, selected-route structured-output support, selector conversion across frames, passive snapshot behavior, and complete charge capture on failure. The documentation/source checks above resolve none of those empirically.
