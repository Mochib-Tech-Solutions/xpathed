# Readiness and resilient XPath — 2026-09-30

The reported YouTube Search result matched a visible button but incorrectly called it off-screen. An isolated managed-browser reproduction returned the same contradiction: a rendered button at `(850, 8)` with dimensions `64 × 40`, verified XPath `//button[@title='Search']`, and `off_screen`. A minimal fixed-header fixture confirmed the local cause: clipping every DOM ancestor falsely excluded a fixed descendant that Chromium could hit-test. Removing only the ancestor's hidden overflow made the old calculation pass. The exact YouTube ancestor chain was not recorded. After the native-geometry fix, the full-site reproduction returned the same XPath and geometry with `inViewport:true`, pointer reception `pass` and readiness `ready`, without executing a click.

## Separate the evidence

There are three distinct checks: whether the language interpretation selected the intended action/target, whether an XPath uniquely identifies that retained node now, and whether a saved XPath survives a specified later page change. Browser `document.evaluate` and node identity establish only the second. Independent semantic fixtures and saved-locator mutation cases establish bounded evidence for the others. [DOM XPath evaluation](https://dom.spec.whatwg.org/#interface-xpathevaluator), [DOM node identity](https://dom.spec.whatwg.org/#dom-node-issamenode).

## Let the browser calculate clipping

Overflow is governed by containing blocks, not simply the DOM-parent chain. Fixed and absolutely positioned descendants can escape an intervening overflow ancestor. Intersection Observer provides browser-computed clipped rectangles; its callbacks are asynchronous and edge-only contact can count as intersecting. Use positive rectangle dimensions, a Document root for each owned frame, one batch per document, and the existing aggregate timeout. Map those local observations through the separately verified frame chain. This replaces incomplete CSS heuristics without another dependency. [CSS overflow](https://www.w3.org/TR/CSS22/visufx.html#overflow), [positioned containing blocks](https://www.w3.org/TR/css-position-3/#def-cb), [intersection computation](https://www.w3.org/TR/intersection-observer/#compute-the-intersection).

Intersection is separate from pointer obstruction, opacity and event success. Retain point hit testing in the target document and each ancestor frame. A native observer returned the expected rectangle in 3.9 ms in one local probe; that is not a performance guarantee. A rendering turn can add latency, so measure complete capture and validation rather than promising that every request is faster.

Playwright's actionability matrix distinguishes actions and observations. Its pointer actions may scroll and trial actions can still apply modifiers; using them as a passive readiness check would change this product's contract. Awaiting one intersection sample also does not establish stability across frames or successful events. [Playwright actionability](https://playwright.dev/docs/actionability), [Locator click API](https://playwright.dev/docs/api/class-locator#locator-click).

## Prefer resilient anchors, verify every candidate

Playwright recommends user-facing semantics and explicit test contracts, and warns against long structural paths or arbitrary nth matches. Its selector generator uses candidate priorities, validation and parent context, with heuristics for generated IDs. Selenium favors IDs when they are unique and predictably stable. These are useful principles, not proof that any one expression is universally best. Playwright's role locators are not standard XPath. External source links describe current upstream code, not an assertion that private generator internals are available in the installed binding. [Playwright locators](https://playwright.dev/docs/locators), [official selector generator](https://github.com/microsoft/playwright/blob/main/packages/injected/src/selectorGenerator.ts), [Selenium locator guidance](https://www.selenium.dev/documentation/test_practices/encouraged/locators/).

The small deterministic improvement is to recognize UUID-shaped IDs, support the common `data-test-id` contract, try safe attribute conjunctions, and reuse semantic table-row or landmark context before positional fallback. Keep unique same-node checks, finite candidate sets and shared deadlines. Grade the previously returned XPath after ID/label updates, wrappers and row reorder; regenerating a new XPath would not test reuse.

XPath string values and XML whitespace normalization differ from accessible names, JavaScript Unicode whitespace and NFC normalization. Preserve sanitized naming and browser verification instead of inserting arbitrary raw text, hidden contents or editable values into XPath. Unsupported semantic text forms may still need structural fallback. [XPath 1.0](https://www.w3.org/TR/1999/REC-xpath-19991116/).

## Preserve action meaning without another inference stage

The existing prompts said `fill (including type)` despite separate action enums. A live regression returned `fill` for an explicit typing step. Distinguish replacement/filling from typing, preserve double/right-click, map checkbox/radio state commands to check/uncheck, and treat multiple selected values as one control target. Display the interpreted action so a mismatch is visible. Native date/time filling differs from general sequential typing. [Playwright .NET actions](https://playwright.dev/dotnet/docs/input), [WAI checkbox](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/), [WAI radio](https://www.w3.org/WAI/ARIA/apg/patterns/radio/).

Structured output constrains response shape, not semantic truth. Keep independent action/target expectations and explicit ambiguity or future-state limitations. This remains target resolution: requested values, option existence, key/modifier effects and application outcomes are not verified or executed. Custom combobox behavior cannot be inferred from its role alone. [OpenRouter structured output](https://openrouter.ai/docs/guides/features/structured-outputs), [WAI combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).

Keep one language-model request. Omit empty optional fields, exact duplicate label/text and constant/private-state placeholders from its input while retaining every candidate, meaningful false state flags, geometry and context. Do not silently truncate candidate coverage or add a second model call to generate XPath. No additional service, dependency or setup step is needed. The remaining limits are arbitrary future DOM changes, model ambiguity/omissions and unexecuted interaction outcomes; a passing smoke example does not qualify all language or sites.
