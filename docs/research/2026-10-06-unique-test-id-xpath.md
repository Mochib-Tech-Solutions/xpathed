# Unique test IDs and XPath text predicates — 2026-10-06

## Assessment

When a target's explicit test attribute already yields one matching node in the relevant tree, and that node is the retained selected target, adding its display text is unnecessary for uniqueness. It changes the locator's contract: the selector now requires both the test identity and the current wording. This is a reasoned recommendation from the sources below, not a guarantee that any third-party test ID remains stable.

The initial investigation inspected commit `d81f4453e1d3bc813959509b2631717a52cd43b9`. The sections describing that baseline are historical observations. The subsequent authorized fix is developed in an isolated worktree from current `origin/main`; the implementation status below distinguishes the selected direction from pending verification. Existing unrelated modifications were left intact.

## What the inspected baseline does

`xpathsFor` first tries each target test attribute alone in a tag-qualified expression, such as `//button[@data-testid='save']`. Its `add` helper requires exactly one evaluated match and object identity with the retained target. A successful expression returns immediately, before ancestor scope, semantic text, ordinary attributes or paired predicates are attempted. A unique target test ID therefore does **not** receive an appended text predicate in this code path. [Browser construction and verification](../../src/Browser/Sessions/BrowserCaptureScript.cs#L471-L486).

Text predicates are constructed eagerly before that first test-attribute attempt. That work is a possible small efficiency improvement, but constructing an unused candidate is different from returning a text-constrained XPath. [Candidate construction](../../src/Browser/Sessions/BrowserCaptureScript.cs#L480-L486).

An expression can still contain both a test attribute and text when the test attribute belongs to an ancestor, or when a repeated target test ID needs a meaningful ancestor whose heading or cell text distinguishes the scope. Here the text provides the identity of the scope or the selected descendant; an ancestor's unique ID does not automatically identify which child was requested. Scoped expressions are attempted only after standalone target test predicates fail. [Context construction](../../src/Browser/Sessions/BrowserCaptureScript.cs#L457-L467), [scoped construction](../../src/Browser/Sessions/BrowserCaptureScript.cs#L486-L494).

Separately, before construction, capture revalidation compares the retained node's current label, text and role against its captured description. This detects changes while resolving the current instruction. It does not require those values to be embedded in the returned XPath. [Retained target validation](../../src/Browser/Sessions/BrowserCaptureScript.cs#L625-L631), [documented selection policy](../resolution.md#preferred-xpath).

The existing browser suite asserts an exact test-ID-only XPath for the About us button. Its saved-locator mutation case also changes a test-ID button's wording from `Save` to `Save changes` and verifies the originally returned locator afterward. These are inspected test definitions, not fresh execution results; no running Browser stack was available during this research. [Exact test-ID assertion](https://github.com/Mochib-Tech-Solutions/xpathed/blob/d81f4453e1d3bc813959509b2631717a52cd43b9/tests/resolution/browser.test.mjs#L537), [saved-locator wording mutation](../../tests/resolution/browser.test.mjs#L1925-L1981).

## The supplied Pinterest example

The user-provided example is `//div[@data-test-id='simple-login-button']//button[normalize-space(.)='Log in']`. Its test attribute identifies the ancestor `div`; it does not directly identify the target `button`. The expression's text predicate selects the named button inside that scope. The first ancestor-context pass tries target test/semantic predicates; it reaches this scoped text candidate before the later bare-tag fallback. [First scope pass](../../src/Browser/Sessions/BrowserCaptureScript.cs#L486-L494), [later bare-tag fallback](../../src/Browser/Sessions/BrowserCaptureScript.cs#L508-L516).

If the test-ID container is unique and contains exactly one matching descendant button, then `//div[@data-test-id='simple-login-button']//button` already selects that button. Under that condition the added text does not improve present uniqueness; it adds a wording requirement. If the container contains multiple buttons, the text can be necessary. The supplied XPath alone does not establish either count, nor the site's intended stability contract. The baseline documented policy retained target semantics within meaningful scope to reject different-label replacements; trying a bare descendant first under an explicit test-ID ancestor would be a deliberate policy change, not merely removal of a redundant syntax fragment. [Documented scope policy](../resolution.md#preferred-xpath).

### Fresh browser observation

On 2026-10-06, a separate background browser visit to the public Pinterest homepage found one `div[data-test-id="simple-login-button"]`, containing exactly one descendant `button`. That button's text was `Log in`; it had neither `data-testid` nor `data-test-id` itself. Read-only browser locator counts returned one match for the supplied XPath and one for `//div[@data-test-id='simple-login-button']//button`. Since the former filters the latter's sole match, both select the same button. The text is redundant for present uniqueness in this observed structure.

This was a fresh public-page observation, not inspection of the exact Browser capture shown in the screenshot. It confirms the structure on that visit; it does not establish Pinterest's future contract or that every variant has the same markup. That read-only Pinterest visit performed no login action or provider call; the later controlled verification is recorded separately below.

## What the primary sources support

Playwright treats test IDs as explicit application/testing contracts and explains that they can remain usable through wording or role changes. Its examples query the test ID directly; content filters narrow repeated matches, including repeated controls inside named product cards. Strict single-element operations reject multiple matches. Consequently, direct test identity and content-based identity are different useful choices rather than attributes that always need to be combined. [Playwright locators: test IDs, filters and strictness](https://playwright.dev/docs/locators#locate-by-test-id).

Playwright's test generator improves a locator when several elements match it. That supports adding disambiguation when needed, rather than treating extra predicates as intrinsically better. [Playwright test generator](https://playwright.dev/docs/codegen#introduction).

`data-testid` is a custom `data-*` attribute, not the standard HTML `id`. HTML allows custom data attributes with arbitrary values and imposes no uniqueness requirement on their values. Standard HTML IDs, in contrast, are required to be unique within their tree. Neither authoring rule substitutes for checking a real page that may violate expectations. [HTML custom data attributes](https://html.spec.whatwg.org/multipage/dom.html#embedding-custom-non-visible-data-with-the-data-*-attributes), [HTML ID](https://html.spec.whatwg.org/multipage/dom.html#the-id-attribute).

XPath predicates filter candidate node sets. If the attribute predicate already produces one target, a text predicate can only retain or remove that match. The `//` form starts from the document root; `.//` searches descendants of the context. Element string values concatenate descendant text nodes, and `normalize-space` normalizes XML whitespace. These semantics do not implement rendered text or accessible-name computation. [XPath 1.0 location paths, predicates and string values](https://www.w3.org/TR/1999/REC-xpath-19991116/).

XPath does not pierce shadow roots. xpathed's separate frame and shadow context remains necessary even if the same test ID occurs only once in a particular tree. A test ID seen once among current-view candidates is insufficient evidence of full-tree uniqueness: hidden or offscreen duplicates can still match the emitted expression. [Playwright XPath limitations](https://playwright.dev/docs/other-locators#xpath-locator), [xpathed current-view boundary](../resolution.md#current-view-boundary).

If wording is itself a test expectation, it can be asserted independently of how the element is located. Playwright provides `toHaveText` and `toHaveAccessibleName` assertions for that purpose. This separation is a recommendation for downstream tests; xpathed remains a Resolver and does not execute assertions. [Playwright text assertion](https://playwright.dev/docs/api/class-locatorassertions#locator-assertions-to-have-text), [accessible-name assertion](https://playwright.dev/docs/api/class-locatorassertions#locator-assertions-to-have-accessible-name).

Selenium similarly recommends unique, predictable IDs and compact readable selectors. Its recommendation concerns ordinary IDs; it is corroborating guidance for avoiding unnecessary selector complexity, not a specification for xpathed's complete ranking. [Selenium locator guidance](https://www.selenium.dev/documentation/test_practices/encouraged/locators/).

## Concrete consequences

For `<button data-testid="save">Save</button>`, these expected outcomes follow from XPath predicate semantics; they are illustrative predictions, not measured browser results:

| Saved expression                                              | Display text changes to `Save changes`, same test ID | A second identical test ID appears                                                |
| ------------------------------------------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------- |
| `//button[@data-testid='save']`                               | Still matches the original node                      | Becomes ambiguous and should fail uniqueness validation                           |
| `//button[@data-testid='save' and normalize-space(.)='Save']` | Stops matching                                       | May remain unique if the duplicate has different text, but is now tied to wording |

For repeated `data-testid="save"` controls, a unique section test ID plus the repeated target ID can be sufficient. For a unique section test ID with several unlabeled child buttons, a bare button descendant is insufficient; target semantics or another supported distinguishing attribute are still needed.

## Resilience audit: dynamic IDs and other changes

The policy must distinguish current uniqueness from a stability contract. An arbitrary ordinary ID, `name`, ARIA label, placeholder or test attribute being unique in one DOM does not establish that its value will survive a later render. Selenium's unique-and-predictable qualification remains relevant. A site-owned test attribute is the best available explicit identity signal in this scope, but even it can be removed, reassigned or generated dynamically. [Selenium locator guidance](https://www.selenium.dev/documentation/test_practices/encouraged/locators/), [HTML custom data attributes](https://html.spec.whatwg.org/multipage/dom.html#embedding-custom-non-visible-data-with-the-data-*-attributes).

React's `useId` produces component-associated IDs for accessibility relationships; its value is related to the component parent path, and its docs discourage treating it as a data key. Therefore literal generated IDs should not be treated as a durable application identity merely because they are currently unique. Native `label/@for` relationships can remain usable when both linked values change together, provided the identifying label itself remains meaningful. [React useId](https://react.dev/reference/react/useId), [existing native-label construction](../../src/Browser/Sessions/BrowserCaptureScript.cs).

The inspected generated-ID filter excludes UUIDs, long hexadecimal sequences, five-or-more-digit sequences, purely numeric IDs and colon-prefixed IDs. It is a conservative heuristic, not detection of every generated ID: a stable `order-12345` is excluded while a changing `field-a7x` need not be. Expanding a regex cannot prove stability. Preserve semantic priority over ordinary-ID fallback and the mutation cases that reject changed-meaning replacements reusing an ordinary ID. [Attribute filter and ranking](../../src/Browser/Sessions/BrowserCaptureScript.cs), [preferred XPath contract](../resolution.md#preferred-xpath).

| Change                                                     | Useful identity when available                                                   | Remaining limit                                                                                                       |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Wording/localization changes                               | Direct test contract; unique descendant type inside a unique explicit test scope | Text, ARIA labels, titles and placeholders may also translate; no generic locator can infer a site's durable identity |
| Target or scope tag changes                                | Wildcard explicit test-attribute anchors                                         | A target found by its type within a scope still depends on that type unless it has its own contract                   |
| Wrappers inserted                                          | Descendant relation under a stable explicit scope                                | Moving the target outside that scope invalidates the expression                                                       |
| Re-render replaces DOM node                                | Saved test-contract expression can locate the replacement                        | Current-request validation must reject a detached retained node; do not silently relocate during resolution           |
| Repeated IDs/control types, hidden or offscreen duplicates | Full-tree uniqueness check and an independently unique explicit scope            | Do not use `[1]`, current visibility or readiness to conceal ambiguous identity                                       |
| Repeated rows reordered                                    | Row-specific explicit contract; meaningful content scope when no contract exists | Content-derived row identity remains sensitive to changing/localized content                                          |
| SVG or other namespaces share a local name                 | Namespace URI plus local name for typed fallback                                 | Explicit wildcard test contracts intentionally identify by the contract rather than element type                      |
| Shadow/frame host changes                                  | Independently verified context chains                                            | XPath cannot cross frame documents or shadow roots by itself                                                          |
| Quotes, Unicode, hidden/editable text                      | Existing literal escaping and privacy-aware text fallback                        | XML-whitespace normalization does not equal rendered text or accessible names                                         |

The table is a source-informed audit, not a claim that all variations were measured. Preserving the exact saved XPath across mutations tests a different property from asking Resolver to construct another XPath afterward. Playwright locators find a current DOM element on each use; xpathed instead validates the retained captured target while resolving and returns a reusable expression. Its current capture must fail when that retained target detaches or changes relevant captured semantics. [Playwright locator introduction](https://playwright.dev/docs/locators#introduction), [xpathed retained-target contract](../adr/0028-validate-retained-targets.md).

One additional concrete source issue is the baseline non-HTML `tag` helper: it uses `local-name()` without the namespace URI. XPath models expanded element names as both a local part and a namespace URI and provides both functions. Two foreign-namespace elements with the same local name can therefore collide under that helper; a saved typed fallback can also match a replacement from a different namespace. Include `namespace-uri()` when a fallback is meant to retain the target's non-HTML type. [XPath node tests and name functions](https://www.w3.org/TR/1999/REC-xpath-19991116/#node-tests), [baseline tag construction](../../src/Browser/Sessions/BrowserCaptureScript.cs).

## Selected implementation direction and verification status

The user authorized the audit, resilient fixes and merge workflow after the initial analysis. The chosen direction is to prefer uniquely verified explicit test contracts without adding display wording: wildcard target test attributes, then unique explicit ancestor test scopes with a uniquely verified descendant target test attribute or target type. The entire scope expression and target expression must remain unambiguous; a hidden/offscreen duplicate still matters. Namespace-aware non-HTML typed fallbacks address the separate name-collision issue. The browser implementation now follows this direction, with accepted behavior recorded in [ADR-0029](../adr/0029-prefer-explicit-test-contracts-for-xpath.md).

This changes saved-locator identity under explicit test contracts. Such locators tolerate copy/locale changes and deliberate tag-independent contract anchors tolerate tag replacement. It does not make every XPath language-independent: without a suitable explicit contract, semantic text and label relationships remain useful fallbacks. It also does not change the English instruction interface, add model calls, bypass current-request revalidation or replace the ordinary-ID changed-meaning safeguards.

No general future-proof guarantee follows from this ranking. A removed/reused contract, new matching duplicate, changed scope membership or changed typed descendant can invalidate a saved locator. Further automatic repair or identity inference would require a separate accepted contract and evaluation; it is not part of this fix.

## Recommendation

Keep the existing first-success policy for a unique explicit target test ID. Preserve full-tree same-node verification and current-request label/text revalidation. Use meaningful scope or semantics when the target test ID repeats; avoid adding current wording solely for reassurance. Do not equate uniqueness now with future identity stability, and do not remove semantic checks from ordinary-ID replacement cases: the existing policy deliberately treats those differently from explicit test contracts.

A narrow implementation opportunity is to attempt standalone test predicates before preparing semantic/text fallback predicates. This avoids unused fallback work when a target test ID succeeds; no measured latency improvement is claimed. The fresh Pinterest observation supports earlier priority for an explicit-test-scope-plus-tag candidate when the scope is unique and the complete expression uniquely matches the retained target. Keep that wording-tolerant identity contract distinct from ordinary-ID and unnamed-scope fallbacks.

The focused real-browser checks first reproduced three failures against the baseline (direct-contract tag replacement, translated scoped controls and namespace collision); the existing duplicate/changed-meaning guard passed. All four checks pass after the fix. The complete real-browser resolution suite passed 135 checks. The provider-free XPath evaluation passed 185/185 cases, 206/206 intended targets, 26/26 saved-XPath mutations and 26/26 fresh mutation resolutions, with no model calls. The shared evaluation set adds translated direct/scoped contracts, repeated target contracts, offscreen duplicate contracts and namespace collision cases. These measurements establish the tested mutations, not universal future stability.
