# Monitor explicitly approved current-view releases

Current release design is superseded by [ADR-0023](0023-simplify-release-evaluation.md). The rules below describe historical decisions and remain relevant to their original artifacts; they are not additional gates for new release PRs.

Accepted, 2026-10-01. The maintainer authorized completing release setup and recurring monitoring with `OPENROUTER_EVAL_API_KEY`, using GitHub Actions failure notifications. This supersedes the earlier deferral of paid scheduled monitoring. Application credentials remain separate and provider key limits remain the spending control.

Policy 3 qualifies contract 4, prompt 8 and capture 5. Keep policy 2 and its historical results unchanged. Preserve the existing numerical quality and latency gates; require thirty distinct current-view held-out cases across ten authored families and one attempt per case. Legacy contracts remain deterministic compatibility evidence. Source/template review and deterministic browser checks precede inference; authored families do not establish production-wide statistical confidence. Reserve held-out families in the authoritative private release state before confirmation, including failed or interrupted waves, so later runs cannot silently reuse exposed data as fresh qualification.

Use the existing prepared accounting protocol for policy 3: bind the exact prepared provider request, reserve durably before the timed Resolver request, reconcile after the provider response, and retain all attempts and charges. The timer includes capture, inference, XPath verification and the runtime pricing path. Deterministic preparation cannot populate the live pricing cache. Fixture setup, independent grading and accounting persistence remain outside this timer. This versioned measurement does not reinterpret older inline-accounting results.

Keep a private approved-release pointer, previous approval and audit on `release-state`. Explicit promotion requires the independently pinned candidate digest, complete artifact-bound qualification, compatible contract, unchanged assets and a passing measured baseline for the frozen sentinels. A changed artifact cannot inherit qualification. Promotion selects the approval; explicit local activation restores the exact Browser/Resolver images, checks ownership, preserves credentials/database volumes and records observed deployment identity. Activation restarts browser sessions. It refuses a running development configuration. Rollback re-verifies the retained previous approval and is always explicit; hosted model weights cannot be rolled back by restoring images.

Nightly monitoring runs at 02:17 UTC from a trusted main-branch orchestrator. It downloads the exact approved source and image IDs, verifies them against the frozen approval receipt, and executes the frozen sentinel list and grader with one fresh attempt per case. No build of current development code, latest-release substitution, automatic promotion, fallback or rollback is allowed. Missing approval or monitoring receipts, altered/missing approved artifacts, transport failures, semantic drift and latency regressions fail the workflow without changing the approval or local application. Record last-started and last-completed checks separately.

The maintainer subsequently approved continued monitoring after qualification evidence expiry. Promotion saves the verified monitoring receipt with the source, bundle, suite, policy, sentinel membership and measured baseline identities in the authoritative approval state. Monitoring uses that record after the original archive expires or is pruned; it never creates a new approval or extends eligibility for promotion. New promotions still require fresh qualification. Older approvals without a monitoring receipt fail closed and require a newly qualified promotion. Activation and rollback retain their existing verification requirements.

Portable private evidence archives preserve original paths relative to the source checkout and integrity digests. Archival does not restart the existing thirty-day qualification-evidence expiry. Retain source/images and sanitized approval history separately from expiring page/provider evidence; operator-owned private release evidence follows the documented retention and pruning procedure.

GitHub sends notifications according to account preferences and the workflow/schedule actor, not administrator status alone. Existing manual failure-email delivery was observed. Verify the controlled manual failure and the first actual scheduled delivery separately. Native Actions schedules are best effort and may be delayed or dropped; no alert is promised for a workflow that never starts. See the [notification research](../research/2026-10-01-release-monitoring-setup.md).

Sentinels use only development/regression families. The shared evaluator rejects held-out sentinel membership, so an early local monitoring run cannot consume fresh qualification families.
