# Select an element before generating XPath

The primary resolver uses sanitized HTML and DOM context to ask a model to select a target element for each action. Ordinary code then constructs XPath expressions and verifies that they resolve uniquely to that same element. This keeps XPath construction grounded in the page and separates locator validity from the model's semantic selection quality. Each action resolution represents one target and may provide alternative XPath expressions for that same target; it does not present competing candidate guesses. The multi-action follow-up in [ADR-0008](0008-resolve-multiple-current-page-actions.md) changes request-level cardinality, preserving this action-level invariant. Other resolution strategies remain possible for comparison.
