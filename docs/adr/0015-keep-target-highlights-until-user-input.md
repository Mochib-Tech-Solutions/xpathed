# Keep all target highlights until user input

The 2026-09-30 follow-up requires every found target to remain highlighted during mouse movement and scrolling, until a browser click/keypress, a new instruction or page/capture invalidation. This supersedes the first-target-only highlighting decision in [ADR-0011](0011-report-observed-readiness-and-one-xpath.md); the legacy `inspectedActionId` remains the first found action for compatibility, not a count of displayed highlights.

Chromium's transient inspection overlay supports one active inspection tool and [deliberately hides on mouse movement](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/inspector/inspect_tools.cc). Use Browser-owned, pointer-transparent decorations around retained verified nodes instead, with closure-owned state and a closed shadow root. Decorations must be excluded from accessibility and capture, cleaned up with their capture, and must preserve target attributes, layout, focus, scrolling and form state. They are temporary DOM additions, visible to page mutation observers; a closed shadow root does not make its host invisible to the page. A client overlay would avoid those additions but require a separate geometry synchronization path across services and the scaled viewer.

Browser retains ownership of node/frame identity and lifecycle. Showing a highlight never executes an instruction. Browser input invalidates the pending capture so a delayed resolution cannot restore highlights after the user has acted; movement and scrolling preserve them. Input notifications older than the active capture are ignored. Navigation, frame changes, tab switches and closure still invalidate captures independently of input.

The 2026-10-01 visibility follow-up uses a thick black-and-white outline so contrasting edges remain visible across light, dark, colored and patterned surfaces without sampling page pixels. Borders trace the visible rectangular portion at viewport and overflow edges. A small visible target (at most 24 CSS pixels on either axis) triggers one 1.2-second spotlight in its owning document: dim the surroundings, keep apertures around every selected target, then fade back to the page. Apertures have a 48px minimum to help locate tiny controls without changing their bounds. Reduced motion skips the spotlight. The existing border lifetime, passive behavior, frame ownership and cleanup rules remain in effect.

The 2026-10-02 readability follow-up places the entire outline outside those visible bounds and removes the interior tint. Offset the stroke center outward by half the 8px outer stroke width; the 4px white stroke stays centered on that same path. Clear every selected interior after drawing so touching or overlapping outlines cannot cover another selected target. This preserves the targets' rendered text, icons and borders. The outline can extend beyond an overflow container; the owning document viewport still clips it, so an edge flush with the viewport has no outward room and only the remaining edges are visible.

The 2026-10-04 follow-up lets hover or keyboard focus on a current response’s XPath hold a steady spotlight around its retained target, at any size. Keep every selected outline and target interior clear; only the hovered target receives the expanded aperture. Exit clears dimming. Reduced motion retains this static effect without animation. Browser revalidates action/node/capture identity and updates the existing overlay instead of rebuilding it; cleared highlights cannot be resurrected. Historical results cannot request it, and the client serializes hover transitions so an earlier request cannot overtake exit or another target.
