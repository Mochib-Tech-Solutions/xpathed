# Keep all target highlights until user input

The 2026-09-30 follow-up requires every found target to remain highlighted during mouse movement and scrolling, until a browser click/keypress, a new instruction or page/capture invalidation. This supersedes the first-target-only highlighting decision in [ADR-0011](0011-report-observed-readiness-and-one-xpath.md); the legacy `inspectedActionId` remains the first found action for compatibility, not a count of displayed highlights.

Chromium's transient inspection overlay supports one active inspection tool and [deliberately hides on mouse movement](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/inspector/inspect_tools.cc). Use Browser-owned, pointer-transparent decorations around retained verified nodes instead, with closure-owned state and a closed shadow root. Decorations must be excluded from accessibility and capture, cleaned up with their capture, and must preserve target attributes, layout, focus, scrolling and form state. They are temporary DOM additions, visible to page mutation observers; a closed shadow root does not make its host invisible to the page. A client overlay would avoid those additions but require a separate geometry synchronization path across services and the scaled viewer.

Browser retains ownership of node/frame identity and lifecycle. Showing a highlight never executes an instruction. Browser input invalidates the pending capture so a delayed resolution cannot restore highlights after the user has acted; movement and scrolling preserve them. Input notifications older than the active capture are ignored. Navigation, frame changes, tab switches and closure still invalidate captures independently of input.
